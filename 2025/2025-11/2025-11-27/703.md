My first thought is to sort the list upon each insertion of a value, after sorting the stream of values we can return the `kth` most element from the end of the list. However this requires a time complexity of O(n log n) upon every insertion of a value. To optimize the solution we can use a min heap instead. We will initialize our stream of numbers to be a min heap and pop the minimum number in our heap until we reach a heap of size `k`. We do this as we only need a stream of size `k` elements since we are only interested in the `kth` largest element, this means that the minimum element in our min heap will always represent the `kth` largest element. 

When we push values to our heap it will exceed size `k` and we can just pop once from the heap then return the minimum value in the heap. One small edge case that we need to account for is the fact that our stream can be of size `k-1` before the insertion of a value. This means that we don't want to pop from our heap only if the size of our heap is lesser than `k`. 

```python
class KthLargest(object):

    def __init__(self, k, nums):
        self.k = k
        self.nums = nums
        heapq.heapify(self.nums)

        while len(self.nums) > self.k:
            heapq.heappop(self.nums)

    def add(self, val):
        heapq.heappush(self.nums, val)

        if len(self.nums) > self.k:
            heapq.heappop(self.nums)

        return self.nums[0]
```

> Time Complexity : `O(log k)`
> 
> Space Complexity : `O(k)`

We need to return a list of `k` coordinates that are closest to the origin (0, 0). My first thought is to create a max heap of size `k`, this will ensure that all `k` elements within the heap are the coordinates that are closest to the origin. We can calculate the distance between two points using the formula `sqrt((x2 - x1)^2 + (y2 - y1)^2)`, these values will be used to determine the `k` coordinates that are closest to the origin in our max heap of size `k`. 

But how do we return the coordinates in a list? Upon each calculation of the distance between two coordinates, we can use a hashmap that maps the distance between two points to its corresponding coordinates.

To start this problem we will initialize a hashmap that will represent a distance to coordinate mapping and a max heap of size `k`. We will then iterate over each coordinate in the input array `points` and create the distance to coordinate mappings to our hashmap whilst also pushing distances to our max heap. 

After doing this we can pop the maximum values in our heap until we reach size `k`. Once we reach size `k` our heap will contain `k` distances of the coordinates that have the shortest path to the origin. We can then use our hashmap to return the coordinates into a results list.

```python
class Solution(object):
    def kClosest(self, points, k):
        mapping = {}
        maxHeap = []
        res = []

        for point in points:
            distance = math.sqrt((point[0] * point[0]) + (point[1] * point[1]))
            mapping[distance] = point
            heapq.heappush(maxHeap, -(distance))

        while len(maxHeap) > k:
            heapq.heappop(maxHeap)

        for distance in maxHeap:
            res.append(mapping[-(distance)])

        return res
```
After submitting the following code I failed a edge case, if two coordinates had the same distance to the origin such as `[[0,1],[1,0]]`, the output would be `[[1,0],[1,0]]` as the hashmap doesn't take into account for different coordinates with same distance values.

One idea that I came up with is to push `(distance, coordinate)` tuples into our heap. This way the heap would be able to heapify based of the distance value in the tuple and we can resolve the mapping issue we had earlier by appending the coordinate of each tuple to our results last when we iterate through our max heap at the end.

```python
class Solution(object):
    def kClosest(self, points, k):
        maxHeap = []
        res = []

        for point in points:
            distance = math.sqrt((point[0] * point[0]) + (point[1] * point[1]))
            heapq.heappush(maxHeap, (-(distance), point))

        while len(maxHeap) > k:
            heapq.heappop(maxHeap)

        for tup in maxHeap:
            res.append(tup[1])

        return res
```

> Time Complexity : `O(n log k)`
> 
> Space Complexity : `O(k)`

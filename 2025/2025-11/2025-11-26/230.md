My first initial thought was to traverse through the entire tree using dfs and store all elements in a list. We can then sort the list and return the kth smallest element. This solution is pretty slow as sorting requires O(n log n) time complexity.

A faster approach to this problem is to traverse the tree in order, this ensures that the smallest elements on the left subtree are accessed first before the right subtree. We will also initialize a global variable `counter`. While we traverse the left subtree we will increment this counter by 1. if the counter is equal to `k` we will return the current node we are on. If the kth smallest value is not in the left subtree, the variable left will equal to `None` and we will continue to traverse the right subtree until the counter is equal to `k`.

```python
class Solution(object):
    def kthSmallest(self, root, k):
        self.count = 0

        def dfs(node):
            if not node:
                return None

            left = dfs(node.left)
            if left is not None:
                return left

            self.count += 1
            if self.count == k:
                return node.val

            return dfs(node.right)

        return dfs(root)
```

> Time Complexity : `O(n)`
> 
> Space Complexity : `O(n)`

I had the initial thought of using a max heap that stores the frequency of each task. This was to ensure the most frequent tasks would take priority over other tasks, guaranteeing the minimum number of CPU intervals to complete all tasks. 

The part that I got stuck on was how I can know what time the frequency values that I pop are able to go back into the max heap. One way of doing this which I had took some hints for was to use a priority queue. Each time we pop values from our max heap we will increment the frequency count by 1 and append `(frequency count, time until ready)` pairs into the queue. The time until ready will be taken by the current time plus `n` where `n` represent the minimum interval of time between a process.

After implementing this I found that we can just look at the left most value of our priority queue each time we pop values from our heap, if the time of the left most value in the priority queue is equal to the current time then we can pop that value from the queue and push it back into our heap.

This process will run while both our priority queue and our max heap are non empty, upon each iteration of this while loop we will increment a global time variable by 1. After the max heap and the priority queue is empty we can return the global time variable which will represent the minimum number of CPU intervals to complete all tasks.

```python
class Solution(object):
    def leastInterval(self, tasks, n):
        count = Counter(tasks)
        maxHeap = [-cnt for cnt in count.values()]
        heapq.heapify(maxHeap)

        time = 0
        queue = collections.deque()
        while maxHeap or queue:
            time += 1
            
            if maxHeap:
                cnt = heapq.heappop(maxHeap) + 1
                if cnt:
                    queue.append([cnt, time + n])

            if queue and queue[0][1] == time:
                heapq.heappush(maxHeap, queue.popleft()[0])

        return time
```

> Time Complexity : `O(n)`
> 
> Space Complexity : `O(1)`

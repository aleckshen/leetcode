This question is the same as the previous daily except we have duplicate elements to take into account. There are three cases to handle:
1. `nums[mid] > nums[r]`, this means that the minimum value must lie in the right region of the array so we can update out left pointer to `mid + 1`.
2. `nums[mid] < nums[r]`, this means that the minimum value must lie in the left region of the array inlcluding the current `mid` value itself, we will update our right points to `mid`.
3. `nums[mid] == nums[r]`, this is the duplicate case we have to take int account, in this case we can decrement `r` by one. The reason that this works is because discarding the right most value will not remove the chance of us missing the minimum value as `nums[mid]` is equivelant. However decrementing `r` by one will give us O(n) worse case insteadd of O(log n).

After our left and right pointers overlap `l == r`, so we can return the position of either pointer which represents the minimum value in a rotated sorted array with duplicates.

```python
class Solution:
    def findMin(self, nums: List[int]) -> int:
        l, r = 0, len(nums) - 1

        while l < r:
            mid = l + (r - l) // 2

            if nums[mid] > nums[r]:
                l = mid + 1
            elif nums[mid] < nums[r]:
                r = mid
            else:
                r -= 1

        return nums[l]
```

> Time Complexity : `O(n)`
> 
> Space Complexity : `O(1)`
